# Team review guide · Saandio TV 0.3

This is an inspectable research build of a native Android TV client. It is not a claim of full source availability, an official client for any named service, or a completed security certification. Test this app and endpoints you control; the application does not include exploits against third-party services.

## Review the product flow

1. Install `dist/SaandioTV-debug.apk` on an isolated Android TV/device. Keep the source revision with your test notes. The debug signing identity supports local upgrades; do not treat it as a distribution signing identity.
2. Open Add-ons. Netflix, Prime and Hotstar are separate NetMirror-backed connections. MovieRulz, TamilTVSerials, TeluguStream and TV channels use the same Saandio navigation, cards, title pages and player.
3. MovieRulz defaults to Telugu + Hindi, interleaved on the first page. Change the language selector, navigate pages, search, open a title, choose a source and observe the bounded source check before playback. Playlist entries and source URLs are supplied by the external repository, not generated by Astra.
4. Catch-up sources show series cards. Open a series, choose a season and episode date, then open the episode and its sources. Back should restore the previous source/episode context rather than sending you to a website or a different app.
5. TV channels defaults to Telugu with all genres. Use All languages + News for the country-wide news directory, or Telugu + All for indexed Telugu channels. Language classification comes from public language feeds intersected with the Indian country directory. Unclassified Indian entries remain under Other Indian languages. This is coverage of the directories, not proof that every Indian/free channel exists or works.
6. Exercise watchlist, reviews, resume, audio/subtitle controls, background-audio preference and media keys. Confirm behavior on a physical TV; a landscape phone emulator is not full TV certification.
7. Open Settings → Source health & research. Export the redacted event log through the document picker. It records provider ID, stage, success and time only; it does not export URLs, response bodies, account IDs, headers or session tokens.

## Build and automated checks

```powershell
gradlew.bat assembleDebug lintDebug testDebugUnitTest
```

Tests use artificial fixtures, not private user accounts or copied authentication cookies. Test coverage includes playlist metadata and duplicate sources, HTTPS restrictions, DRM-directive rejection, Indian channel membership, language/genre filtering, bounded paging, series grouping, episode-specific URLs, stream-type detection, separate NetMirror platform identities, encrypted session origin binding and research-log redaction.

Read `docs/VERIFICATION.md` for the actual run results and limits. Passing fixture tests proves client behavior under those fixtures; it does not prove a remote server will accept a connection.

## Trust boundaries worth studying

- **Untrusted source data:** catalogs, playlists, metadata and artwork are inputs. Data never becomes downloaded executable add-on code. The app does not execute website scripts, popup handlers or APKs. The one WebView is a locked-down official YouTube IFrame embed (`youtube-nocookie.com` only, no cookies, no new windows); it is not a general browser.
- **Network transport:** source requests use HTTPS, bounded bodies, timeouts and redirect limits. Playback headers are restricted to Referer, Origin and User-Agent. Playlist Cookie/Authorization directives and CRLF-bearing values are rejected. Network redirects and DNS rebinding still warrant a dedicated egress-policy review; HTTPS-only is not a complete local-network/SSRF defense.
- **Session storage:** NetMirror sessions use AES-GCM with an Android Keystore key. The canonical API origin is authenticated as additional data. Changing API origin clears the prior session. Cache identity includes the source connection/revision so old-account data is not presented as a fresh catalog for a replacement session. Legacy plaintext source sessions are migrated when accessed.
- **Runtime credentials:** encrypted-at-rest storage is not protection against a compromised running device. Hardware-backed/StrongBox properties, rooting, memory inspection, backup behavior and key invalidation must be assessed on real devices. Device/cloud transfer exclusions are explicit in the manifest resources.
- **Media boundary:** a small-prefix check detects common HLS/DASH/MP4 and HTML/gate responses. It is not complete media validation or a guarantee against a later segment failure. Media3 and platform codecs parse the stream; platform/dependency patching and malformed-media testing remain important.
- **External proxies:** the supplied movie playlist includes third-party proxy URLs. Saandio TV consumes the listed URLs; it does not deploy that worker, copy its implementation or claim control over its logging, availability or security. Never attach private source cookies to those proxy requests.
- **Telemetry:** the built-in research export uses an allowlist. Android/platform diagnostics and independent network tools are separate and can expose more information; review those outputs before sharing them with a team.

## Defensive test exercises

- Import duplicate IDs, an oversized catalog, an invalid URL, a URL with user-info, HTTP media, long titles, unusual Unicode and malformed metadata. Errors should leave the prior imported catalog intact.
- Feed fixture playlists with quoted commas, missing metadata, repeated sources, credential headers, CRLF text and DRM license directives. Ensure parsing stays bounded and credentials do not become playback headers.
- Replace a provider fixture with malformed JSON, HTML, HTTP 401/403/404, slow responses, redirect loops and an expired signed media URL. No error should silently launch a browser, bypass the source's access control or count as verified playback.
- On your own fixture server, test session replay across a different origin, malformed/tampered envelopes, device key deletion and process restart. Verify failure without leaking plaintext into the research export.
- Change language, genre, source endpoint and session while a request is pending. An old result must not overwrite the new connection's screen. Disable a source and verify it does not fetch playback/episode data until enabled again.
- Test long catalogs and rapid D-pad navigation with memory/network profiling. Artwork should load only for visible cards; catalog pages should remain bounded. Watchlist/search presentation is currently capped at 96 visible results and should receive separate pagination work if larger libraries are in scope.
- Test local-network destinations and rebinding only in an authorized lab. The current client is a research baseline, not a hardened egress sandbox.

## What robust services should enforce

Enforce entitlement and authentication on the server, use narrowly scoped and short-lived media authorization, validate account/device/session scope, rotate/revoke credentials, protect signing keys off-device, and use supported DRM where the content requires it. Client obfuscation, hidden URLs and popup-based gates are not substitutes for server enforcement. None of this app's source checks certify the security or authorization design of a third-party service.

## Known source constraints

The NetMirror reference is an unofficial client whose published servers have returned gates or connection failures during this work. The three native add-on entries do not make those services available without an accessible endpoint and a valid source-issued session. Tested TamilTVSerial video links have also returned non-video redirects. Such cases remain explicit native failures. A public playlist or an experimental/noncommercial purpose does not establish complete functionality or content rights.
