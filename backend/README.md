# Saandio Catalog API

A small server-side proxy so the Android TV app can load TMDB movie and TV catalogs **without
shipping a TMDB credential in the APK and without asking viewers for a key**.

```
Android TV app ──HTTPS──▶ Saandio Catalog API (/api/tmdb) ──Bearer token──▶ api.themoviedb.org/3
```

- The TMDB credential lives only in the server environment (`TMDB_READ_ACCESS_TOKEN`, or the v3
  `TMDB_API_KEY`). It is never returned in responses or written to logs.
- Only the read-only catalog endpoints the app uses are forwarded (trending, now playing, popular,
  discover, genre lists, search, details, seasons, watch providers, person). Unknown paths and query
  parameters are rejected or dropped; `include_adult=false` is always enforced.
- Responses carry `Cache-Control` (`s-maxage` + `stale-while-revalidate`) so a CDN absorbs most
  traffic, and a weak `ETag` so the app's conditional requests get `304 Not Modified`.
- Failures are explicit: `503 not_configured` (no credential), `502 upstream_auth` (TMDB rejected the
  credential), `503 upstream_rate_limited`, `504 upstream_unavailable`.

When no catalog service is configured the app still works: it shows keyless open data (Wikidata
films, TVMaze episode schedules), Live TV and Sports, and never prompts the viewer for a key.

## 1. Get a TMDB credential (developer/operator only)

Follow TMDB's official guide: <https://developer.themoviedb.org/docs/authentication-application>.
Create an API application in your TMDB account settings and copy the **API Read Access Token**
(preferred) or the v3 API key. Review TMDB's API terms of use; attribution ("This product uses the
TMDB API but is not endorsed or certified by TMDB") is already shown in the app's Settings.

Do not use keys shared publicly or generated by third parties.

## 2. Run locally

```bash
cd backend
cp .env.example .env          # fill in TMDB_READ_ACCESS_TOKEN; .env is git-ignored
node --env-file=.env dev-server.js   # Node 20.6+; or export the variables yourself
curl http://localhost:8787/api/health
curl "http://localhost:8787/api/tmdb?path=/discover/movie&with_original_language=te&page=1"
npm test                      # node --test, no network needed
```

## 3. Deploy (Vercel, zero config)

`api/tmdb.js` and `api/health.js` are standard Node serverless functions.

```bash
cd backend
vercel link                                  # create/link a project with this folder as the root
vercel env add TMDB_READ_ACCESS_TOKEN production   # paste the token when prompted (stored encrypted)
vercel env add SAANDIO_CLIENT_TOKEN production     # optional, see below
vercel deploy --prod
curl https://<your-project>.vercel.app/api/health  # expect "tmdbConfigured": true
```

Any Node 18+ host works the same way: expose `/api/tmdb` and `/api/health` with `lib/tmdb-proxy.js`
and set the environment variables in that host's secret store.

## 4. Point the app at it

In the app repository's `local.properties` (never committed) or as CI environment variables:

```properties
catalog.api.base=https://<your-project>.vercel.app
# optional, must match SAANDIO_CLIENT_TOKEN on the server
catalog.client.token=<random string>
```

Environment equivalents: `SAANDIO_CATALOG_API_BASE`, `SAANDIO_CATALOG_CLIENT_TOKEN`. Rebuild the APK.
The base URL must be `https://`; the build fails otherwise. Settings → "Movie & TV catalog" shows which
route the build uses.

`catalog.client.token` is an abuse deterrent, not a secret: anything inside an APK can be extracted.
Real protection comes from the endpoint whitelist, CDN caching and, if needed, rate limiting or a WAF
on the host.

## Developer keys

`tmdb.api.key` in `local.properties` is compiled into **debug builds only** (release builds always get
an empty value), and Settings → "Developer · metadata keys" accepts a personal key on a test device.
Either one makes that device call TMDB directly, which is handy before the service is deployed.
